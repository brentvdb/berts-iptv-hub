# Bert's IPTV Hub

A small Windows service that logs into your Xtream IPTV account **once** and shares that single
connection with every TV in the house running Bert's IPTV.

- The provider only ever sees **one device and one connection** (your PC).
- Every TV gets the same channel list, EPG and **shared favourites**.
- All TVs follow one "now playing" state:
  - Pick a channel on any TV and every TV switches to it.
  - Open the app on another TV and it goes straight into the live stream.
  - Press Back on any TV and every TV leaves the player.
- **No transcoding.** The stream bytes are copied unchanged, so the hub uses well under 1% CPU and around 100 MB of RAM.

## Install (Windows, no Docker)

1. Download **`BertsIptvHub-Setup-<version>.exe`**. Get it from the repo's **Releases** page, or from
   **Actions → Hub installer (Windows) → latest run → Artifacts**.
2. Run the installer and enter your Xtream server URL, username and password. Then choose a **TV password**,
   which your TVs will use to log into the hub.
3. That's it. The hub runs as an auto-start Windows service with crash recovery, and port 8090 is opened for
   your local network only. The status page opens at the end of setup and is always at `http://<pc-ip>:8090`.

To change settings later, use **Start → Bert's IPTV Hub → Edit hub settings**. It opens the settings in
Notepad and restarts the hub after you close it.

To upgrade, run a newer installer over the top. Your settings, favourites, cache and logs are kept, and the
settings file also survives an uninstall.

## Versions

The repo-root `VERSION` file is the single source of the version number, shared with the TV app (for example `1.0.0`). It's used for:

- the installer file name (`BertsIptvHub-Setup-1.0.0.exe`) and the build artifact name (`…-build12`)
- the exe's file version (`1.0.0.12`) and the "Apps & features" entry
- the version shown on the status page (`v1.0.0 (build 12)`), plus `GET /api/version`, `/api/status`
  and the `hub.version` field in the login response

To release a new version, bump `VERSION`, push, then run both workflows manually with **Publish a GitHub
release** ticked. That creates release `v1.1.0` with the installer and the APK attached.

### Building locally (optional)

With the .NET 8 SDK and Inno Setup 6 installed:

```powershell
dotnet publish hub/src/BertsIptvHub.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o hub/publish
& 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe' /DAppVersion=1.0.0 hub\installer\BertsIptvHub.iss
```

The artwork (icon, logo and installer images) is generated by `hub/installer/assets/make_art.py`.
The tests in `hub/tests` use a fake one-connection Xtream provider: run `fakeprov.py`, start the hub
pointed at `http://127.0.0.1:9900`, then run `run_tests.py`.

## Settings (`appsettings.json` → `Hub`)

| Setting | Default | Meaning |
|---|---|---|
| `ListenUrl` | `http://0.0.0.0:8090` | Address and port the TVs connect to |
| `LocalUsername` / `LocalPassword` | `home` / `changeme` | Login the TVs use for the hub |
| `JoinBufferKB` | 4096 | Recent stream data kept so a joining TV starts at once, from the latest keyframe |
| `IdleTimeoutSeconds` | 20 | Close the provider connection when no TV has watched for this long |
| `UpstreamRetries` | 5 | Reconnect attempts if the provider drops the stream |
| `UpstreamStallSeconds` | 15 | Treat the stream as dead if no data arrives for this long |
| `UpdateCheckMinutes` | 30 | How often the background updater checks whether the channel list or EPG is due for an update |
| `CatalogCacheHours` | 6 | How often the channel list (and any other cached API lists) is updated from the provider |
| `EpgCacheHours` | 12 | How often the full XMLTV guide is updated from the provider |
| `ShortEpgCacheMinutes` | 10 | Cache time for `get_short_epg` / `get_simple_data_table` |
| `ExtraEpgEnabled` | true | Use free public XMLTV guides for channels your provider has no guide for |
| `ExtraEpgSources` | epgshare01 UK1 + ZA1 | Public XMLTV / XMLTV.gz URLs to merge in. Other epgshare01 files: IE1, US2, US_SPORTS1, AU1, … |

**Background updates:** the hub downloads the channel list and EPG from the provider by itself, on the
schedule above. TVs are always answered straight from the hub's copy, even while an update is running or if
the provider is down. Only the very first request for something, on a brand-new install, waits for the
provider. The status page shows when the channel list and EPG were last updated.

Logs are in `C:\BertsIptvHub\data\logs` (Start menu → Hub logs) and are kept for 14 days. Favourites are stored in `data\favorites.json`.

If you change `ListenUrl` to a port other than 8090, you also need to change the Windows Firewall rule "Berts IPTV Hub (TVs)" to match.

## How the TV app talks to the hub

### 1. Xtream-compatible API

Point the app at `http://<pc-ip>:8090` with the hub login. These work as they would against the provider:

- `player_api.php` (login and every `action=`). Responses are cached. In the login response,
  `server_info` is rewritten to the hub, and an extra `"hub": {...}` object is added so the app can tell it's talking to the hub.
- `xmltv.php` (full EPG) and `get.php` (M3U with URLs rewritten to the hub)
- Live: `/live/{user}/{pass}/{id}.ts`. **Always request `.ts`**, because the hub relays MPEG-TS.
- `/movie/...`, `/series/...`, `/timeshift/...` and `/streaming/timeshift.php` are passed through with seeking (Range) support.

Movies, episodes and catch-up also use the one provider slot. Starting one stops live TV on all TVs, and the reverse.

### 2. Sync WebSocket: `ws://<pc-ip>:8090/sync?username=..&password=..&device=Lounge%20TV`

The hub sends these to the TV:

```json
{"type":"state","mode":"live","streamId":101,"name":"SuperSport 1","icon":"...","epgChannelId":"...",
 "startedAt":"2026-11-24T08:13:01Z","viewers":2,"version":7,"reason":null}
{"type":"state","mode":"idle","version":9,"reason":"stopped by Lounge TV"}
{"type":"state","mode":"vod","vodKind":"movie","vodId":"movie:555.mp4","name":"Movie 555",...}
{"type":"favorites","live":[101,102],"vod":[],"series":[]}
```

The current state and favourites are sent as soon as a TV connects. Ignore any state whose
`version` is lower than the last one you saw.

The TV sends these to the hub:

```json
{"cmd":"hello","device":"Lounge TV"}
{"cmd":"play","streamId":101}     // switch everyone (optional: requesting the .ts URL does this too)
{"cmd":"stop"}                    // everyone leaves the player
{"cmd":"getState"}  {"cmd":"ping"}
```

What the TV app should do:

| Event | App action |
|---|---|
| App opens and state is `live` | Go straight to the player with `streamId` |
| State changes to `live` with a different `streamId` | Switch the player to that channel |
| State changes to `idle` | Leave the player and return to the channel grid |
| User presses Back in the player | Send `{"cmd":"stop"}` |
| Player gets end-of-stream or an error | Don't retry blindly. Wait for the next `state` message, which tells you whether to switch or exit |

### Guide matching (`http://<pc-ip>:8090/epg`)

Channels with no guide from your provider are matched to the public guides automatically, by channel ID or by
channel name (`UK: SKY SPORTS F1 FHD` ⇔ `Sky Sports F1 HD`). The **Guide matching** page shows where every
channel's guide comes from. From there you can pick the right public channel by hand, put a channel back to
automatic matching, or set it to "no guide". It asks for the TV password, and your choices are saved in
`data\epg-map.json`. Event-only channels such as FloRugby have no public guide.

### 3. EPG worked out on the hub

The hub parses the provider's XMLTV once after each guide update, so TV boxes don't have to:

- `GET /api/epg/now?username=..&password=..[&ids=1,2,3]` returns now/next for every channel (keyed by stream id)
- `GET /api/epg/{streamId}?username=..&password=..&hours=12` returns listings from one hour ago onwards
- `GET /api/epg/report` and `POST /api/epg/map` (`{"streamId":1,"sourceChannelId":"SkySp.F1.HD.uk"}`; `""` = none,
  `null` = automatic) are used by the Guide matching page

Programme times are Unix milliseconds: `{"title","desc","start","end"}`.

### 4. Favourites (REST)

All of these need `?username=..&password=..`. Every change is pushed to all TVs over `/sync`.

- `GET /api/favorites`
- `PUT /api/favorites/{live|vod|series}`, with a JSON array body `[101,102]` that replaces the list and keeps its order
- `POST /api/favorites/{kind}/{id}` adds an id, and `DELETE /api/favorites/{kind}/{id}` removes one

### 5. Other endpoints

- `GET /api/state`, `POST /api/play/{id}` and `POST /api/stop` need the hub login.
- `GET /api/status` and the status page at `/` are read-only and never show credentials.

## Notes

- Only one thing can play at a time, because that's what one provider connection allows. If two TVs pick different channels, the last pick wins and every other TV follows it.
- When a TV joins a running stream it starts at the most recent keyframe, so the picture appears straight away. Each TV can be up to about one GOP (1–2 s) behind the others.
- When switching channels, some providers take a moment to free the slot. The hub retries automatically, which can add about a second.
- Every TV gets its own copy of the stream over your home network (for example, 4 TVs × 8 Mbps ≈ 32 Mbps).
